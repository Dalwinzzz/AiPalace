# 指令文件维护约定（CLAUDE.md / AGENTS.md）

适用：维护任意位置的 `CLAUDE.md` / `AGENTS.md`（全局 / 项目 / 子目录）。

## 1. 内容分流

主文件是 always-on 注入，必须精简，只保留：

- **全局规则约束**（硬约束：默认语言、ConfigFile 读取策略、提交规范触发等）；
- **when-to-use 触发**（何时该用某能力——触发器必须常驻，否则模型不知何时去读细节）；
- **系统级注入**（身份、对话风格、安全边界）。

**how-to 等操作细节**移入子文档 `AiPalace/context/howto/<主题>.md`，按需 `Read`，不常驻上下文。

## 2. 索引指针写法

主文件的指针**只保留纯指向 + 加载时机**，不复述子文档内容：

- ✅ `→ 见 <子文档绝对路径>（实际要用时再读取）`
- ❌ 在指针里枚举"具体流程 / 参数 / 边界"——那是子文档的职责，复述即冗余。

## 3. 措辞：精确指令，非解释

指令文件（主文件与子文档）是给**模型**的指令注入，不是给人看的说明：

- 只写约束模型行为的精确指令；
- 删去元说明 / 旁白——如"本文件由 X 指向、何时加载、为何这样设计"之类对人的解释。

## 落点

| 类型 | 落点 |
|------|------|
| 主文件（薄壳 + 指针） | `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、各项目 `CLAUDE.md` / `AGENTS.md` |
| how-to 子文档（按需加载） | `AiPalace/context/howto/<主题>.md` |
