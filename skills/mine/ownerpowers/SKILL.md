# ownerpowers · 公司项目工作流引擎

先判任务该走多重的流程（triage 分档），再按档编排。
核心理念——**把复杂度交给判断；简单任务零仪式，复杂任务才上纪律**。

## 第一步：triage（先判线，再判档）

**判线**（二选一，模糊则问一句"这是开发需求还是排查问题？"）：

| 输入信号 | 线 | 剧本 |
|---|---|---|
| 需求原型 / PRD / "加功能" / "改成…" / 接口字段变更 | 需求开发线 | `workflows/feature-dev.md` |
| 工单 / 报错堆栈 / 异常日志 / "线上出问题" / "查为什么" / 数据对不上 | 运维排查线 | `workflows/ops-triage.md` |
| 与开发 / 排查无关的杂活 | 杂活直做 | 直接做（T0） |

**判档**（升档阶梯，默认 T0，命中任一即升）：

- **T0 直做**（默认）：查询 / 读代码、单文件局部改、文档·配置编辑、一眼可见的笔误级修复。
- **T1 轻纪律**：改动 **≤5 文件** / 非显而易见的 bug / 改业务逻辑·查询·接口实现（有副作用但可逆）/ 写新的小功能单元。
- **T2 全纪律**：跨模块·改公共 API·接口契约·DB schema·迁移 / 不可逆·高风险 / 需先设计的多步功能·重构 / 同一 bug 已修 **≥2 次**仍不好 / 你**显式要求**走完整流程。
- **T3 决策地图**：**两条同时成立**才升——① 一次会话装不下（预计 ≥3 次会话）；② 还有多个相互依赖的**未定决策**（有雾）。
  只满足①是"活多"，那是 T2 分多次执行，不是 T3。

> **就地升档**：按初判档位开工，中途发现"简单任务"变复杂（牵连文件超预期 / bug 复发 / 上下文快耗尽而决策还没定）→ **立即升档，不硬撑**。

## 第二步：线 × 档 路由

| | **T0 直做** | **T1 轻纪律** | **T2 全纪律** | **T3 决策地图** |
|---|---|---|---|---|
| **需求开发线** | 直接改 + self-check | feature-dev 精简（跳设计，验证必走）+ 停② | `grilling` 脑暴 → `spec-architect` 出 spec → test-first → 验证 + 停①② | `workflows/decision-map.md`：画地图 → 一次会话解一个决策 → 雾清完降 T2 |
| **运维排查线** | 一眼修 + 验证 | 根因调查按需 → 修 → 验证 + 停② | 根因调查强制 → 根因定调① → 修 → 回归 → 验证 + 停② | 同上（少见：跨系统、根因空间大到一次查不完时才用） |

## 决策点门控

| 档 | ① 方案 / 根因定调 | ② 提交前 |
|---|---|---|
| T0 | 不停 | 不停（直做，靠护栏兜底） |
| T1 | 不停 | **停**（摊"改了哪些文件 + diff 概要 + 提交计划"） |
| T2 | **停**（摊"打算怎么改 / 根因是什么"） | **停** |
| T3 | **每个决策条目各停一次**（这就是 T3 的全部内容） | 不适用——T3 不落代码 |

> ①归属动态绑定：T2 若委托了 `spec-architect`，其 Confirm 门即视为①，**不重复问**。

## 🚧 不可逆护栏（全档通用，不随档放松）

删数据 / 改生产配置 / 执行非只读 SQL / push 到远端 —— **无论哪档哪步，一律额外停下显式确认**。

## 横切

- **纪律**：test-first / 根因优先 / 完成前验证三条铁律与**本地跑测试的命令、栈相关根因入口** → `disciplines.md`（要跑构建/测试或排查前读）。
- **能力**：worktree 隔离与 subagent 调度（含**分支命名硬规范**与**外派禁区：决策不外派**）→ `policies.md`。
- **委托**：脑暴 / 设计访谈 → `grilling`；结构化设计 / 出 spec → `spec-architect`；SQL（评审 / 优化 / 查数 / DDL）→ `sql-expert-dba:sql-expert-router`；接口契约对齐 → Apifox MCP `mcp__apifox-new-mcp__*`。
- **状态播报**：每进入一步先用一行告知"现在在 [步骤] · [做什么]"，让用户随时可打断。

## 公共步骤（`references/`，按需读取）

`step-A` 接口契约对齐 / `step-B` 代码定位 / `step-C` 构建自测 / `step-D` SQL 委托 / `step-E` 提交 / `step-F` 排查产出。
