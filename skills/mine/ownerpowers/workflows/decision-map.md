# T3 · 决策地图（跨会话大需求）

> triage 判为 T3 后读取。适用两条线，需求开发线为主。
> 设计借自 `wayfinder`（mattpocock），去掉 issue tracker 依赖，改为仓内文件承载。

## T3 在解决什么

一个需求大到一次会话装不下，而且**从这里到终点的路还看不清**——不是活多，是有雾。
直接开干的下场是：上下文耗尽在半路，下次会话不知道从哪续，已经想清楚的东西丢失。

T3 的产出是**一张决策地图**，不是代码，也不是 spec。雾清完之后，每块可执行的东西降 T2 走 `feature-dev.md`。

## 铁律：只定不做

**T3 只产出决策，不落生产代码。**

那股"这个我直接改了算了"的冲动，通常不是效率，是**你已经走到地图边界、该收尾降档的信号**。识别它，别顺着它走。

例外只有一种：**前置型**条目（见下），做完某件事之后决策才有得谈。

## 地图落盘

```
docs/decision-map/<需求名>/
├── MAP.md                      ← 索引，每次会话开头只读这一份
└── decisions/
    ├── 001-<决策名>.md
    └── 002-<决策名>.md
```

**地图是索引，不是仓库**：一个决策的正文只活在它自己的文件里，`MAP.md` 只留一行摘要 + 链接。
这条不是洁癖——它是 T3 省上下文的全部来源：每次会话只加载「地图 + 一个决策文件」，不是全部。

**默认不 `git add`**（同 spec 落盘规则）：先 `git check-ignore` 看是否已被忽略；未被忽略也不主动纳入追踪，你明确要求才 `git add -f`。

### MAP.md 格式

```markdown
# <需求名>

## 终点
<走完这张地图会得到什么——一份可交付的 spec / 一个锁死的方案 / 一次就地改造完成。
一两行。每次会话开工前先对齐它。>

## 约束与背景
<适用于本需求全程的前提：涉及哪些模块、哪些不能动、相关区域口径、要遵守的既有约定>

## 已定决策
<!-- 索引：每条一行，够判断相关性即可，细节点进去看 -->
- [001 <决策名>](decisions/001-xxx.md) — <一行结论>

## 待定条目
- [ ] 002 <条目名> · 类型 · 阻塞于 001

## 迷雾区
<!-- 看得见但还讲不清楚的，不切成条目 -->

## 范围外
<!-- 判定超出终点的，连同理由；不再回来 -->
```

## 迷雾：什么该开条目，什么该留在雾里

判据是「**现在能不能把问题说精确**」——**不是**「现在能不能答」。

- **开条目**：问题已经问得清楚了，哪怕被别的条目阻塞、现在动不了。
- **留在迷雾区**：还问不清楚。**不要把雾预先切成条目大小**——它比条目粗，等前沿推进过去，一片雾可能裂成三个条目，也可能一个都不剩。

解掉一个条目会清掉它前方的雾。清出来能说精确的，当场升格为新条目，并从迷雾区删掉——**同一件事不许同时活在两个地方**。

## 范围外：单列，且永不毕业

雾只在**朝向终点**的方向聚集。超出终点的工作不是雾，它是范围外。

已经开出来的条目，如果发现它坐落在终点之外（开图时划错了，或被某个结论暴露出来）：**关掉它**，在「范围外」留一行（要点 + 为什么在范围外）。它不进「已定决策」——那栏记的是实际走过的路，划边界不是路上的一步。

范围外的东西只有在**终点被重画**时才回来，那时是一张新地图，不是接着这张走。

## 条目四型

> 下面是**条目的分类标签**，不是 skill 名——除「拷问型」外都不对应任何可调用的 skill。

| 型 | 谁来做 | 用在什么时候 |
|---|---|---|
| **拷问型** | **必须有你在场** | 默认型。委托 `grilling` skill，一次一问收敛 |
| **查证型** | 可派 subagent | 决策卡在"某个库/接口/历史实现到底怎么回事"，查这个要读很久 |
| **原型型** | **必须有你在场** | 卡在"我说不清但我觉得不对"。做个粗东西给你骂，比继续抽象讨论快。一次性代码，用完即弃、不进主干 |
| **前置型** | 视情况 | 纯体力活（开权限、备数据、跑一次导出），做完决策才有得谈。**唯一允许动手的型** |

⚠️ 标「必须有你在场」的条目，**agent 不得替你作答**——见 `policies.md` 的外派禁区。

## 入口一：开图

1. `grilling` 先定**终点**——终点定了范围才定，所以它第一个定。
2. `grilling` 再来一轮，这次**广度优先**：横着扫一遍整个空间，把开放决策和现在就能动的第一批捞出来，别顺着任何一条深挖。
   - **如果扫不出雾**——路已经清楚了，一次会话装得下——**那你不需要地图**。停下来告诉用户，改走 T2。
3. 写 `MAP.md`：终点、约束、已定决策留空、雾写进迷雾区。
4. 把现在能说精确的开成条目，标好类型和阻塞关系。
5. **查证型**条目可以当场并行派 subagent 去查（见 `policies.md`）。
6. **停**。开图就是一次会话的活，不顺手解任何条目。

## 入口二：续图

1. 只读 `MAP.md`，不读全部决策文件。
2. 选条目：你指定了就用你指定的；否则取「无阻塞待定条目」里的第一个。播报选了哪个。
3. 解它——需要哪个已定决策的细节，**这时候**再点进那个文件读。按类型走对应剧本。
4. **★停**：摊结论等你拍板。**这就是 T3 的决策点①**，每个条目各停一次。
5. 拍板后：写 `decisions/NNN-*.md`，`MAP.md` 的「已定决策」加一行，条目移出待定。
6. 清雾：新能说精确的升格为条目；发现有条目超出终点的，判范围外；发现结论推翻了地图别处的，就地改掉或删掉那些条目。
7. **一次会话只解一个条目**（查证型除外，它派出去、不占主线上下文）。解完就停。

## 收尾：降 T2

待定条目清空、迷雾区清空 → 地图完成。此时：

- 终点是「一份 spec」→ 把地图交给 `spec-architect` 当输入（已定决策就是它的既定前提，不用重新讨论）
- 终点是「锁死方案」→ 到此结束
- 终点是「就地改造」→ 按已定决策拆成若干 T2，逐个走 `feature-dev.md`

无论哪种，**降档那一刻起决策点门控换回 T2 的①②**，不再走 T3 的一条目一停。
