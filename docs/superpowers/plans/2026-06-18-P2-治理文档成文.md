# P2 治理文档成文 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 把已 commit 的治理 spec（`docs/superpowers/specs/2026-06-18-aipalace治理与设计哲学-design.md`）落成**稳定的规范文档**——`PHILOSOPHY.md` + `docs/governance/` 全套。spec 是"一次性设计决策记录（为什么/取舍）"；governance 是"长期遵循的规范（是什么/怎么做）"，口吻面向"未来维护者照此执行"。

**Architecture:** 分层规范集——顶层 `PHILOSOPHY.md`（最高准绳，P1-P9），`docs/governance/` 下 content-assets（skills/rules/context/memory）+ product-assets（injection/plugins）+ creations + evolution，README 作索引。每个文档单一职责、相互交叉引用。

**Tech Stack:** Markdown 文档。验证 = 结构完整性 + 内部交叉引用有效 + 关键规范点对照 spec 齐全（无 pytest）。

## Global Constraints

- 内容真源是 spec：每个 governance 文档**依据 spec 对应节转写为规范口吻**，不照搬"背景/为什么"，只留"规范/标准/流程"。spec 的决策依据需要时用一句话 + 链接到 spec/ADR，不展开。
- 设计哲学总纲 = P1-P9（见 spec §3），措辞 verbatim 采用 spec 的 P1-P9 定义。
- category 封闭集 = `workflow / method / sql / stack / docs / design / diagram / media / meta`（9 类）。
- skill 三级路径 = `skills/<class>/<source>/<skill>/`，class ∈ {mine, enterprise, community}。
- 内容资产四分：skills / rules（硬触发） / context（软·模型自选） / memory（按需 pull）；context 与 memory 各有 INDEX（when→what）。
- 派生形态 = symlink（ADR-0005，已在 P1 落地）。
- 所有文档用中文，commit 用 `<type>(<scope>): <subject>` 格式（commit-msg hook 强制）。
