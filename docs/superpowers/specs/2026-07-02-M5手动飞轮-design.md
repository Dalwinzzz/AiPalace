## 1. 背景与目标

ADR-0013 落地了 vault/memory 五层结构与 SessionStart 注入，但 04-FEEDBACK 飞轮中枢当前为空壳（仅 `journal/.gitkeep`），沉淀仍走 `/wrap` 直写。M5 交付**手动飞轮**：

- G1：`/ai-palace` 命令（`/wrap` 超集）编排 capture → distill → approve → promote 全链。
- G2：`tools/memory/` 确定性 python 内核——六维打分 / 去重 / 晋升门 / 白名单校验 / 写盘全部可复算，**LLM 永不决定"是否进长期库"**。
- G3：双工具（Claude Code + Codex）共用同一 journal / candidates / DREAMS / 内核。
- G4：补漏通道 `sweep` 蒸馏"从没跑过 /ai-palace 的历史会话"。
- G5：验收后退役 `/wrap`。

非目标（N）：

- N1：**无 cron / 无夜间自动**——全部手动触发（用户既定决策，推翻同事的无人值守形态）。
- N2：不移植同事 `[llm]` subprocess CLI 抽取机器（provider fallback / output_file_arg / 每机器 CLI 路径）——抽取一律由在场 agent 完成。
- N3：不做 native memory 收敛（M4 范畴）；不动 SessionStart 注入机制。

## 2. 锁定决策

| # | 决策 | 依据 |
|---|------|------|
| D1 | 捕获架构 = **A 主（会话内抽 + journal 底料）+ B 补（sweep 扫漏网）**，A 先做完再做 B | 用户拍板：双通道，平时 A、偶尔 B |
| D2 | 跨工具共用靠**共享数据层**（journal/candidates/DREAMS/内核全在 vault 绝对路径），不靠扫对方 transcript；双工具各自派生 `/ai-palace` 入口 | A 比 jsonl 扫描更工具无关；同事 jsonl 机器是为无人值守而生，我们手动有会话上下文 |
| D3 | B 抽取 = **B1 会话内 sweep**：脚本纯 python 读 jsonl 导出 user 发言 blob，抽候选交在场 agent；无 subprocess | 用户选 B1；Mac+Windows 零 CLI 路径包袱 |
| D4 | dest 路由 = **LLM 提议 + config 白名单校验 + 人审批可改** | 用户拍板；"是否进库"仍由确定性 gate 把守，路由提议不破防幻觉铁律 |
| D5 | 六维权重/阈值忠实移植同事 config（relevance .30 / frequency .24 / diversity .15 / recency .15 / consolidation .10 / richness .06；promote_threshold .50 / min_freq_global 2 / dedupe .72） | 实证沿用，跑不顺再调参（参数全在 config.toml 单一源） |
| D6 | UPDATE 一律**追加并标注，不覆盖原文**；00-RULES 晋升只追加到文末 `## 蒸馏晋升（待归位）` 暂存段 | 同事同款安全策略；不让脚本乱动身份卡/规则组结构 |
| D7 | `/ai-palace` = `/wrap` 超集：vault 候选走飞轮；`context/rules/<域>.md` 工程规则**直写旁路不过六维**；新文件 INDEX 接线保留 | 工程规则是程序记忆，与"我是谁"relevance 语料不适用 |
| D8 | promote 写 00-RULES 是 vault.md 授权的唯一合法路径（candidates 审批 → promote），不违"不越权"契约 | vault.md §5 原文 |

## 3. 数据流

```
【A · 主 · 每会话手动】
/ai-palace
 ① 在场 agent 复盘本会话 → 抽 纠正/决策/偏好/观察，逐条提议 type/scope/dest
 ② 追加 journal/<today>.md（append-only；行内 <!--sig {...}--> 携带提议元数据）
 ③ 调 core.py distill：扫 journal 近 scan_days 天 → merge(0.78) → 六维打分
    → dedup vs 全 vault(≥.92 NOOP / ≥.72 UPDATE / else ADD) → gate(≥.50 且 global freq≥2)
    → 白名单校验 dest → 追加 candidates.md + DREAMS 留痕
 ④ 候选渲染回对话 → 用户审批（对话勾选 或 Obsidian 手勾 [x]）
 ⑤ 调 promote.py：仅处理 [x] → 按 action/dest 确定性写盘 → 标 ✅done → DREAMS 留痕
 ⑥ 只暂存 vault/memory/ 变更并提交（禁止 add -A）

【B · 补 · 偶尔 · phase 2】
/ai-palace sweep
 ① gather_sessions.py 纯读 ~/.claude/projects/**/*.jsonl + ~/.codex/sessions/**/rollout-*.jsonl
    近 N 天且不在 sweep-ledger 的会话 → 导出 user 发言 blob（复用同事 _walk_user_text 容错解析）
 ② 在场 agent 从 blob 抽候选（同 A①）→ 写 journal → 走同一 ③–⑥
 ③ 更新 sweep-ledger（`tools/memory/.sweep-ledger.json`：已扫会话文件清单；机器本地状态，gitignore）
```

**不变量：** 在场 agent 只做「抽候选 + 提议 scope/dest」；脚本做「打分 / 去重 / 把门 / 白名单 / 写盘 / 留痕」；人做「审批」。六维分数只能来自脚本输出，命令中禁止 LLM 自估分数。

## 4. 模块布局

## 5. 文件格式约定

### journal 行（兼容同事前缀 + 扩展 sig 元数据）

```markdown
- 决策: <一句话陈述> <!--sig {"type":"decision","scope":"project:enterprise/zhijin","dest":"01-PROJECTS/enterprise/zhijin/skc-activity.md","source":"claude:<session-id-前8位>"}-->
```

- 前缀封闭枚举：`偏好:` / `决策:` / `纠正:` / `观察:`（观察不进候选，仅留底）。
- `<!--sig-->` 可缺省：缺省时 scope=global、dest 由确定性 fallback 映射（preference/correction → `00-RULES/`暂存；decision+project → 对应域）——保证手写 journal 行也能进飞轮。
- merge 合并相似行时 freq/sources/dates 累加，sig 取最新一条。

### candidates.md 条目（沿同事约定，promote 解析协议）

```markdown
- [ ] <statement> <!--cand {"id":"cYYYYMMDD-NN","action":"ADD|UPDATE","dest":"...","type":"...","scope":"...","freq":2,"score":0.61,"conf":"high"}-->
  - 证据: freq=2 · 来源 claude,codex · 日期 2026-07-01, 2026-07-02
  - 六维: relevance=0.42 frequency=1.00 diversity=0.67 recency=1.00 consolidation=0.42 richness=0.80
```

- `[x]` = 批准；留 `[ ]` = 暂缓；删行 = 否决（DREAMS 留痕）。dest 非法时标 `"action":"INVALID"` 并在证据行说明原因，用户改 dest 后可再跑 promote。
- promote 落地后行内 `<!--cand` 改 `✅<!--done`，防重复晋升。

### DREAMS.md

沿同事格式：每次 distill / promote 追加一节（扫描量 / 候选数達标暂缓 / 晋升清单 / 否决清单）。

## 6. 确定性内核细节

### corpus 双语料（比同事精细化的一处）

- **relevance / consolidation** 语料 = `00-RULES/**.md`（"与我是谁的相关度"）。
- **dedup** 语料 = `00-RULES/**.md + 01-PROJECTS/**.md`（"是否已存在于长期库"）——同事只查 00-RULES，我们项目记忆主要在 01-PROJECTS，不扩会漏判重复。

### 六维公式（照搬 distill.py score_all）

`rel=best_similarity(stmt, rules语料)`；`freq=min(1, freq/max(2,max_freq))`；`div=min(1, 来源数/3)`；`rec=1-(today-newest)/scan_days`；`cons=rel`；`rich=min(1, len/60)`。加权和保留 3 位小数；conf：≥.66 high / ≥.50 medium / else low。

### gate（照搬）

NOOP 直接暂缓；score ≥ promote_threshold 达标；**scope=global 且 freq < min_freq_global(2) 强制不达标**（跨项目铁律须跨会话重复出现，靠 journal 累积）。暂缓条目记 DREAMS 不进 candidates。

### routing 白名单（config.toml，D4）

```toml
[routing]
rules_files = ["00-RULES/identity.md","00-RULES/tech-stack.md","00-RULES/dev.md","00-RULES/flow.md","00-RULES/ops.md"]  # 封闭枚举，只可追加暂存段
projects_globs = ["01-PROJECTS/projects/**.md","01-PROJECTS/enterprise/**.md","01-PROJECTS/tech/**.md","01-PROJECTS/workflow/**.md","01-PROJECTS/reference/**.md"]
```

- dest ∉ 白名单 → 标 INVALID，绝不写盘。02-SOURCES / 03-MAPS 暂不作为晋升落点（YAGNI，需要时改 config + 补测试）。
- 01-PROJECTS 新文件允许：promote 用 `_template/note.md` frontmatter 骨架创建；命令随后按 /wrap 步骤 4 给 INDEX 决策树接线（agent 做，因需要触发关键词语义）。
- 00-RULES 只追加 `## 蒸馏晋升（待归位）` 暂存段（D6/D8），归位进 f-规则结构由用户手动整合。

## 7. /ai-palace 命令编排（/wrap 超集）

| 步 | 动作 | 执行者 |
|----|------|--------|
| 1 | 复盘会话抽候选，按 wrap 路由表+INDEX 提议 type/scope/dest；工程规则类候选单独分组 | agent |
| 2 | vault 类候选写 journal（带 sig）；工程规则类走**直写旁路**：`context/rules/<域>.md` 直接合并写入（含新域 symlink 两跳，继承 /wrap 步骤 3） | agent |
| 3 | `python tools/memory/core.py distill` → 输出候选块 | 脚本 |
| 4 | 渲染候选表（含六维/证据/dest），征询审批；用户口头勾选 → 改 candidates.md `[x]` | agent+用户 |
| 5 | `python tools/memory/promote.py` → 写盘+留痕；新 01-PROJECTS 文件补 INDEX 接线 | 脚本+agent |
| 6 | `git add vault/memory/ && git commit -m "context(ai-palace): <摘要>"`（只暂存 vault/memory 与 context/rules 具体文件，**禁止 add -A**） | agent |
| — | 无候选：输出"本次会话无新沉淀候选"，journal 仍留观察行（可选） | agent |

`sweep` 子模式（phase 2）：步骤 1 之前先 `python tools/memory/gather_sessions.py --days N` 拿 blob，其余同 A。

## 8. 测试与验收

- TDD：`test_core.py`（journal 解析含 sig 缺省 / merge 累加 / 六维可复算——同输入同输出 / dedup 三态 / gate 含 min_freq_global / 白名单 INVALID）；`test_promote.py`（checkbox 解析 / done 防重 / 追加不覆盖 / 00-RULES 暂存段 / 01-PROJECTS 新建带模板 frontmatter / 缺失 dest 跳过告警）。临时 vault fixture，不碰真 vault。
- 验收（M5-A）：真实会话跑一轮全链——journal 落行、candidates 出候选且六维数字来自脚本、审批后正确晋升、DREAMS 两段留痕、重跑 distill 同输入分数一致、candidates 已 done 不重复晋升。
- 验收（M5-B）：sweep 能发现并蒸馏一个未 wrap 过的历史会话，ledger 防重扫。

## 10. 风险与边界

| 风险 | 对策 |
|------|------|
| journal 忘写 → freq 累积不足，global 候选永达不了标 | 这正是 gate 本意（重复不够不晋升）；确需即刻晋升的全局规则可在审批时人工改 scope 或走 M4 后的规则通道 |
| SequenceMatcher 对中文语义近似度偏保守 → 漏判 UPDATE | 沿用同事阈值起步（D5）；参数集中 config.toml，跑不顺凭 DREAMS 数据调参，不引入 embedding 依赖（零依赖铁律） |
| Codex 侧 `/ai-palace` 唤起机制未实测 | plan 阶段实测钉死（P5）；最坏退化为 Codex 里手动粘贴命令文即可跑（内容同源） |
| Windows 侧 symlink 派生 | 既有 P9 待决项管理，不在本 spec 扩大 |
| 敏感信息进 journal | journal 属 vault，走 git；沿用 secrets 红线（`$secret:NAME`），命令步骤 1 明示"凭证类不落 journal" |
