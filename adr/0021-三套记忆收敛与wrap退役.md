# ADR-0021：三套记忆收敛（方案 C）与 `/wrap` 退役

- 状态：已接受
- 日期：2026-08-03
- 决策人：dalwin
- 关联：承接 [ADR-0020](0020-注入机制实测纠偏.md)（实测中发现问题）；执行 `evolution.md` §6.3 的 M5-C；取代 `reference/cross-tool-memory.md` 旧「两侧对账」规范

## 背景

ADR-0020 的注入实测挖出一个比原问题更大的事：**本机同时跑着三套记忆系统，互不知情，已在重复沉淀同一份事实。**

| 系统 | 位置 | 谁在写 | 本轮清点体量 |
|------|------|--------|------|
| Claude auto memory | `~/.claude/projects/<repo>/memory/` | Claude 自动 | 20 个 project 目录，约 450KB |
| Codex memories | `~/.codex/memories/` | Codex 自动 | MEMORY.md 64KB + raw 79KB + 17 份 rollout |
| AiPalace vault | `AiPalace/vault/memory/` | 人工 + 飞轮 | 32 个 note |

后两套默认开启、自动写入、每会话注入，且**都是机器本地的**——换台机器就没了，也不进版本控制。

实锤证据：在 Java 项目里问 Codex 本地 Maven 仓库路径，它答得完全正确，但来源不是 AiPalace 的 `context/rules/java-spring.md`（Codex 侧对 `context/rules/` 零接线），而是它自己 `MEMORY.md` 第 33 行独立学到的同一条事实。**同一条硬事实两份副本、各自演化、无同步**——P1 单一真源在记忆层实际已破。

## 决策

### 方案 C：自动记忆当入口，vault 当归档

三选一里选 C（A = 硬事实归 vault 但保留自动记忆噪音、人工捞回；B = 关掉自动记忆让 vault 独大）。理由：飞轮机制（`/ai-palace`）已存在且跑过两轮，A 的人工负担太重，B 等于逆着工具演进方向走、白扔两个工具自带的自动积累能力。

**分工与铁律**（已写入 `01-PROJECTS/reference/cross-tool-memory.md`）：

1. 工具原生记忆 = **入口层**，只承载"尚未归档的本机新发现"。
2. vault = **归档层 · 唯一 SOT**，跨工具、跨设备、进版本控制。
3. 一条事实归档进 vault 后，**工具侧原处删除、留指针，不留副本**——留副本就是两份各自演化。
4. **不给工具侧补第二份副本**：ADR-0020 曾考虑给 Codex 补 `AGENTS.md` 把 `context/rules/` 灌过去，本 ADR 明确否决——那是在造第三份副本。

### 首轮归档执行结果

**先修 vault 自身的过期条目**（"保证 vault 为最新"的前提）：
- `reference/skills-root.md`：原文仍把 `~/Library/CodeRepo/AI/` 整个目录当 SOT、列 `superpowers/` fork 与 `~/.agents/skills` 双跳拓扑——全部过期，重写为 registry 驱动的现行拓扑。
- `reference/cross-tool-memory.md`：原文是 T6/T9 过渡期的「两侧对账」规范，重写为本 ADR 的三系统分工。

**Claude 全局 `-Users-dalwin`（18 条）**：**全部**已被 vault 覆盖，整体清空改指针。其中三条内容**已过期错误**——`context_sediment` 仍指向 dalwin-workflow、`skills_root` 仍列 superpowers fork、`saas_repos` 指向 2026-04 的临时 worktree 路径——vault 侧已是修正版，直接丢弃不回迁。

**Claude `-Users-dalwin-Library-CodeRepo`（4 条）**：三个个人项目（RiceRoamClub / CodeIsland 蒸馏 fork / DailyDragon）vault 确实没有，归档为 `01-PROJECTS/projects/` 三个 note；commit 钩子规范一条由 PreToolUse hook 每次注入，无需记忆。

**Codex `MEMORY.md`（17 个 Task Group）**：按域把 `Reusable knowledge` / `Failures` / `User preferences` 迁入 vault 十一个文件（含新建 `wavetrans.md`、`gsskservers.md`、`codex-dream-skin.md`），原文件 63910 → 2156 字节，只留归档对照表与指针。

**其余 10 个 per-project Claude memory（skc* 等）**：**内容保留**，只在 MEMORY.md 顶部加统一指引头。它们是逐 repo 的深度项目知识，与 vault 的 `skc-*.md` 有交叉但未逐条核对；无差别删除会毁掉 vault 没有的东西。列为**二轮归档**待办。

> 归档采用**追加**而非合并：每个 vault 文件末尾加一节「自 Codex memories 首轮归档」，并显式标注"未与上文逐条去重，命中同一主题以更近日期为准"。宁可暂时留重复，不冒覆盖既有内容的风险。

### `/wrap` 退役（执行 evolution.md §6.3 的 M5-C）

`/ai-palace` 飞轮已跑两轮，用户确认可独立承接。删 `commands/wrap.md` 真源与 `~/.claude/commands/wrap.md` 派生；PHILOSOPHY / injection / commands / memory / vault 五处指引改指 `/ai-palace`；`evolution.md` §6.3、§6.4 划线收敛。

M5-B `gather_sessions.py` sweep 通道**未实现即放弃**：它的定位是"补 `/wrap` 漏掉的会话"，`/wrap` 没了这个补漏需求就该由飞轮自身覆盖，不值得单独造一条通道。

## 后果

**正面**：记忆层的单一真源恢复——稳定事实只在 vault 一处，工具侧只剩指针。Codex 每会话注入的记忆索引从 64KB 降到 2.2KB；Claude 全局 memory 从 18 条降到 1 张指针表。三条已过期错误的事实（dalwin-workflow / superpowers fork / 临时 worktree）不再每会话被注入。命令层只剩 `/ai-palace` 一条沉淀路径，不再有两命令并行的语义歧义。

**取舍 / 待观察**：
- **自动记忆会重新长出来**——这是设计使然，不是失败。指引头的作用是把新增的东西导向"待归档"而非"另立真源"；判断标准是下次归档时工具侧攒的是否都是 vault 尚无的新料。
- **二轮归档待办**：10 个 per-project memory（约 400KB，`skcinfant` 152KB 最大）需逐条与 vault `skc-*.md` 核对后归档去重。
- **首轮归档留了重复**：Codex 迁入的内容未与 vault 上文逐条去重，各域文件末尾会有主题交叉。列为二轮一并处理。
- 备份留在本次会话 scratchpad `memory-backup-20260803/`（704KB，含双工具原始记忆全量）。**它随 scratchpad 生命周期存在，不是长期归档**——若二轮归档前需要回查原始记录，应尽早另存。
