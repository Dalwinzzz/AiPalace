# ADR-0020：注入机制实测纠偏（rules 触发语义 / identity 直注 / PHILOSOPHY 去 include）

- 状态：已接受
- 日期：2026-08-03
- 决策人：dalwin
- 关联：细化 [ADR-0016](0016-M4全局指令整合-共享规则单一源与native-stub派生.md)（always-on 注入构成）；发现的三套记忆并存问题由 [ADR-0021](0021-三套记忆收敛与wrap下线.md) 承接

## 背景

本地 harness 迭代第二步（注入机制）。勘察发现 governance 对机制 B（path-scoped rules）的描述是**推断**而非实测，且 always-on 预算里存在声明与实现不一致的项。按 P5「实证选型，不照搬」，先挂 `InstructionsLoaded` hook 做实测再改。

## 实测方法

新增诊断探针 `tools/hooks/audit_instructions.py`，临时注册进 `~/.claude/settings.json` 的 `InstructionsLoaded`（matcher 空 = 全 reason），逐事件记录 `load_reason` / `file_path` / `globs` / `trigger_file_path` 为 JSONL。跑完即摘除，settings 与备份逐字节比对还原。

> 实际 payload 与官方文档所列有出入：**没有** `file_content` 字段，**另有** `memory_type` / `globs` / `trigger_file_path`。本 ADR 以实际 payload 为准。

## 决策

### 1. 修正 rules 触发语义（原描述错误）

原 governance 两处写"**工作目录（cwd）匹配**时自动注入"。三组对照实验推翻：

| 场景 | 结果 |
|------|------|
| cwd = Java 项目根，不读任何文件 | ❌ `java-spring.md` 未注入 |
| 同一 cwd，Read 一个 `.java` | ✅ 注入，`load_reason: path_glob_match`，`trigger_file_path` 指向该文件 |
| cwd = AiPalace，Read **工作区之外**的 `.java` | ❌ 未注入 |

**正确语义：读取工作目录树内匹配 `paths` 的文件时触发。** 第三组尤其重要——它比官方文档那句笼统的 "when Claude reads files matching the pattern" 更严格，glob 是相对工作目录树匹配的，读工作区外的同类文件拉不到规则。

推论写进规范：`paths` 按"这个域会打开哪些文件"设计，不是按"在哪个目录启动"设计。已更新 `content-assets/rules.md` §3 与 `product-assets/injection.md` 机制 B 全节。

### 2. Claude 侧机制 B 确认健康；Codex 侧确认无接线

Claude：两跳软链正常解析，`file_path` 直接落到 AiPalace 真源，`memory_type: User`，`globs` 从仓内文件读出，前端 `.tsx` 同样验证通过。**不需要改动。**

Codex：项目树上溯至根**无任何 `AGENTS.md`**，`context/rules/` 在 Codex 侧零消费——原文档所称"Codex 目录树 AGENTS.md 方案"从未落地，属 P9 未申报的隐性漂移，现已在 injection.md 显式标注为「无接线」。

**但不补接线**：实测中 Codex 在 Java 项目里被问本地 Maven 仓库路径与参数，答案完全正确，来源是它自己的原生记忆 `~/.codex/memories/MEMORY.md`（第 33 行明确记着 `/Users/dalwin/Library/Repository`、`saas/settings.xml`、JDK 8）。补一份 AGENTS.md 只会让**同一条硬事实存在第三份副本**。此问题的正解是记忆层收敛，交 ADR-0021。

### 3. identity.md 并入 hook 直注

INDEX 声明它"常驻·进会话必读"，但 hook 只注入 `operating-rules.md` + `INDEX.md`。实测模型确实会按指示去 Read（transcript 命中，答案正确），代价是每会话多一次 round-trip 换 1087 字符。

声明与实现取齐：**改为直注**（`inject_index.py` 的 files 元组加入 `00-RULES/identity.md`，顺序在 operating-rules 之后、INDEX 之前），INDEX 相应改口"常驻三项，均由 hook 直注，无需再 Read"。

### 4. `CLAUDE.md` 去掉 `@PHILOSOPHY.md` 全文 include

实测看到 `PHILOSOPHY.md` 以 `load_reason: include` 在 session_start 全文进上下文（2361 字符），而 `CLAUDE.md` 紧接着的九条精要表讲的是同一件事。改为指针：**要改结构 / 推翻决策 / 判定原则冲突时再读全文**。

## 后果

**正面**：always-on 预算 14403 → 13232 字符（identity +1087 直注、PHILOSOPHY −2361），且省掉每会话一次 Read；governance 里两处错误的机制描述改为实测结论并留下可复现的实验矩阵；Codex 侧的注入缺口从"隐性漂移"转为"显式已知"。

**取舍 / 待观察**：
- 预算只降了 8%——大头 `INDEX.md`（6393 字符，占 48%）本轮**未动**。INDEX 瘦身 / 按 cwd 裁剪子树属档 2，需先看清记忆层收敛（ADR-0021）后的最终形态再做，避免改两遍。
- 探针 `audit_instructions.py` 留仓作为回归工具：**任何改注入机制的动作，前后各跑一次**，用事实而非推断验证效果。它不常驻注册，用时临时挂、用完摘。
